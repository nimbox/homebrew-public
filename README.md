# nimbox/public

The nimbox Homebrew tap:

```sh
brew tap nimbox/public
brew install nimbox/public/tower
```

Formulas live at the repository root and are **generated by GoReleaser** on
each tool's release — do not edit them by hand; the next release overwrites
them.

## Tools in private repositories

Homebrew downloads release assets anonymously, so a formula pointing at a
private repository's release fails with 404. Those formulas download through
the GitHub API instead, using `lib/private_strategy.rb` (shared by all of
them), and require a token on the installing machine:

```sh
export HOMEBREW_GITHUB_API_TOKEN=<a PAT that can read the tool's repository>
```

One export, once, covers every private tool in the tap. The tool's binary
still authenticates its own way (crew credentials, etc.) — the token is only
for fetching the download.

To add a new private tool, its `.goreleaser.yaml` `brews` entry needs
exactly two lines; everything else is the normal GoReleaser tap setup:

```yaml
brews:
  - name: <tool>
    repository:
      owner: nimbox
      name: homebrew-public
      token: "{{ .Env.TAP_GITHUB_TOKEN }}"
    download_strategy: GitHubPrivateRepositoryReleaseDownloadStrategy
    custom_require: lib/private_strategy
```

Tools in public repositories (nimboxctl) need none of this — plain generated
formulas work as-is.
